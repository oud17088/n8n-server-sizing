# n8n服务器配置：从1核1G到4核8G，把自建 n8n 的 CPU、内存、硬盘和节点选法一次讲清楚

自建 n8n 卡住大多数人的地方，不是 Docker 命令，而是"我到底该买多大的机器"。买小了，Code 节点跑到一半进程被杀；买大了，一年白交几百块。更麻烦的是网上一半教程给出的配置口径互相打架——官方说 320MB 内存起步，第三方教程说至少 4GB。

这篇不绕弯子，先从 n8n 官方的资源口径讲起，再对着雨云云服务器的实际档位，把"该买哪一档"这件事落到具体的核数、内存和价格上。

## n8n 吃资源的地方，和你想的不一样

n8n 官方部署文档给出的参考值是：CPU 最低 10 CPU cycles 并按需扩展，内存 320MB–2GB，数据库 512MB–4GB SSD，SQLite 或 PostgreSQL 均可。文档里同时写明了一句关键的话——n8n 不是 CPU 密集型应用，内存需求通常先于 CPU 成为瓶颈；一个空闲的 n8n 实例大约只占 100MB 内存。

也就是说，n8n 本体很轻，真正吃内存的是你写的工作流。官方举的例子很直白：多数节点只是把数据传给下一个节点，但 Code 节点在处理数据时会生成预处理和后处理两份副本，一旦碰上大文件（图片、PDF、批量表格），可用内存能被瞬间吃光。

第三方教程的口径普遍更保守。多份部署指南给出的最低配置是 1 核 2G 内存加 20GB 硬盘，生产环境建议 2–4 核、4–8GB 内存、40–80GB SSD；也有教程把内存在 1GB 列为"能跑但别指望稳定"。这些说法并不矛盾，官方给的是软件本身的下限，第三方的数字是"留给工作流出错的余量"。

你实际要选的，就是这两个数字中间的那一段。

## 按工作流规模倒推配置，比看参数表更快

不用去记内存和核数的对应关系，按你打算用它干什么倒推就行：

- **学习和试手**：每天几条定时任务，节点不超过十个。2 核 2G 内存，30GB 硬盘就够，一年下来成本很低。
- **日常生产**：有 webhook 触发、有 API 对接、有几条每天定时跑的数据同步。2 核 4G 或 4 核 4G 起，硬盘 40GB 以上，建议直接上 PostgreSQL。
- **高频触发或大文件处理**：webhook 每小时被敲几百次，或者流程里要处理图片、PDF、批量导出。4 核 8G 起步，硬盘 60GB 以上，配合队列模式拆 worker。

只有一个判断标准值得反复强调：**内存比 CPU 先崩**。如果你预算有限，宁愿选核数少一档、内存多一档的机型，也不要反过来。

## 硬盘和数据库，比 CPU 更容易踩坑

三个具体问题，买机器之前想清楚：

**第一，SQLite 还是 PostgreSQL。** n8n 默认创建 SQLite 数据库，配置简单，个人用、工作流不多的场景没问题。但随着执行历史累积，SQLite 在并发写入时会出现性能瓶颈。如果你打算长期用、工作流较多或者多人协作，一开始就上 PostgreSQL 更省事——中途从 SQLite 迁移需要额外做数据迁移工作。

**第二，硬盘到底要多大。** 执行历史、日志和凭据都堆在数据库里，30GB 起步能跑，但如果你开了执行记录的完整保存，几个月就可能吃紧。雨云的云盘支持弹性扩容，重庆机房的高速固态是 0.4 元/G/月、机械盘 0.1 元/G/月，所以不必一次买大，先 30GB 起步再按需加更划算。

**第三，容器数据持久化。** 官方明确提醒：在容器化环境中要确保数据卷被持久化并挂载，否则容器停止后重启，数据会全部丢失。另外 n8n 实例重启期间错过的 Cron 或 Webhook 执行无法恢复，如果你要求业务 100% 不断线，需要在前面加一层能缓存请求的代理。

## 带宽、流量和节点，是 n8n 用户最容易漏掉的一段

n8n 挂 webhook，意味着你的服务器会被公网反复敲。这一段有三件事绑在一起考虑：

**流量怎么算。** 雨云云服务器分"不限流量"和"大带宽限流量"两类，限流量机型按上下行合计计费，每月用不完的流量自动叠加、次月不清零，用完后会被限速（重庆机型限速到 5M）。n8n 日常调 API 的流量确实不大，但你要是用它传文件、备份数据、做媒体处理，流量会比你预想的高不少。

**IP 类型怎么选。** 雨云国内节点默认是 NAT 共享 IP 模式，允许开通 10 个端口映射；需要独立公网 IP 的话要额外加购，约 80 元/月/个。n8n 走 5678 端口加反向代理访问，如果你只是自己用、能接受带端口的地址，NAT 模式就够；想让 n8n 用标准 443 端口对外提供 webhook，独立 IP 会省掉一堆麻烦。

**要不要备案。** 这一点比配置更容易被忽略：雨云国内节点的 HTTP 业务用域名访问，需要先完成备案与过白。如果你不想走这套流程，直接选香港或美国洛杉矶节点，免备案，n8n 装完配个域名就能上。

## 机器买回来之后，这几个动作别省

雨云的云服务器支持预装宝塔面板、1Panel 等常用管理面板和运行环境，也支持 Linux 与 Windows，装 Docker 这类基础环境不必从裸系统开始折腾。剩下这几件事仍然要自己确认：

- **放行端口**：22（SSH）、5678（n8n 界面）、80 和 443（反向代理与证书验证）。只开 5678 不配 HTTPS 是最常见的省事做法，代价是登录凭据在公网上裸奔。
- **用 Docker 部署**：官方镜像为 `docker.n8n.io/n8nio/n8n`，更新时拉新镜像即可，不用手动处理依赖。数据卷挂到 `/home/node/.n8n`。
- **别关安全 Cookie**：网上流行的 `N8N_SECURE_COOKIE=false` 只是本地测试用的绕路方案，正确做法是在前面加一层反向代理，用 Let's Encrypt 签证书跑 HTTPS。
- **时区一定要设**：把 `TZ` 和 `GENERIC_TIMEZONE` 设成 `Asia/Shanghai`。不设的话，你写的每天 9 点定时任务会按 UTC 跑，变成下午 5 点触发，而且很难第一时间反应过来是这个原因。
- **备份**：官方建议做夜间备份。备份加密密钥和备份数据库是两件事，密钥丢了，数据库里的凭据就取不出来。

## 几个高频问题

**n8n 必须 4 核起步吗？** 不需要。n8n 官方文档明确说它不是 CPU 密集型应用，2 核足以应付绝大多数场景。核数的意义在于并发执行多个工作流时互不拖慢。

**1 核 1G 到底能不能跑？** 能跑。风险在内存，官方给出的内存区间本身就包含 320MB 这一档，但那是指软件空转。你的工作流才是变量。

**选国内节点还是香港、美国节点？** 看两件事：是否需要备案，以及访问 n8n 界面的人在哪里。国内节点访问延迟低但域名要走备案流程；香港和美国节点免备案，适合快速上线，代价是延迟高一些。

**自建和官方的 n8n Cloud 怎么选？** 自建的成本主要是一台服务器的年费，好处是数据在自己手上、工作流执行不受套餐额度约束。如果你只是偶尔跑几条流程，官方云服务省事；一旦执行量大起来，一台 2 核 4G 的服务器就能把成本优势拉开。

**买之前能先试吗？** 可以。云服务器和游戏云产品支持 1 元试用一天，另有 7 天无理由退款（每账号限 3 次）作为兜底。先跑通你自己的那条工作流，再决定要不要按年付。
